# SpreadsheetBench — real spreadsheet manipulation (OJ-style multiple test cases)

## Source

Renmin University of China et al., **SpreadsheetBench: Towards Challenging Real World Spreadsheet Manipulation**, arXiv **2406.14991**,
NeurIPS 2024 Datasets and Benchmarks. Repository https://github.com/RUCKBReasoning/SpreadsheetBench ;
data https://huggingface.co/datasets/KAKA22/SpreadsheetBench ; leaderboard https://spreadsheetbench.github.io/ .
License: CC BY-SA 4.0.

Get it: download `spreadsheetbench_912_v0.1.tar.gz` from HF (about 96 MB, about 168 MB extracted) and extract it to `data/spreadsheetbench/`,
which gives `all_data_912_v0.1/{dataset.json, spreadsheet/<id>/<n>_<id>_{input,answer}.xlsx}`.

## Description

- 912 instructions (Cell-Level 561, Sheet-Level 351), from real posts on 4 forums such as ExcelForum and MrExcel, rewritten by GPT-4 and manually verified;
  answers are generated by applying the formulas or VBA from the post replies to the spreadsheets. 905 instructions have 3 test cases (same instruction, different data or positions), 2729 in total.
- Evaluation compares only the cell values within `answer_position`; upstream first recalculates formulas with LibreOffice / Excel (`open_spreadsheet.py`),
  then reads them with openpyxl `data_only=True` for comparison. Upstream's color comparison code is commented out.
- scenario: `all`, `cell`, `sheet` (by instruction type).

## Pitfalls

- **Formulas are not recalculated**: formulas written by openpyxl have no cached values, so without recalculation they read back as None. The Knosis scorer always recalculates with LibreOffice before evaluation
  (requires LibreOffice; `KNOSIS_SOFFICE` can specify the path). Results of a few functions may differ between LibreOffice and Excel.
- `answer_position` is written inconsistently: sheet-name quotes sometimes missing on one side, lowercase column letters, full-width colons, whole columns (`A:G`), end point without column letters (`BD2:308`);
  the scorer handles all of these. Some sheet names have leading/trailing spaces.
- In upstream's current `evaluation.py`, `proc_path` points to the input file (the line for model output is commented out), so running it directly compares the input with the answer.
- Some answers use TODAY() / NOW() (e.g. computing age from a birth date), and their cached values were computed on the annotation day; the scorer recalculates such answer files together with the output.
- In some cases the sheet name in `answer_position` does not match the file (e.g. `Sheet 2` vs `Sheet2`), and the upstream script simply marks them wrong; the scorer matches after removing spaces and ignoring case.
- A few instructions come with `.xlsm` (macros); the exporter skips them by default (`-o xlsm=true` enables them).
- Handing back the input spreadsheet unchanged also earns a small score (the answer region already has some correct values); the evaluation report shows this as a reference baseline.
- The Verified 400 subset (2025-12) has only 1 case per question and the top entries are near saturation; this entry uses the full 912 set.
