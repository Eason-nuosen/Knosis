# Who&When — failure attribution for multi-agent systems (which agent, which step)

## Source

Zhang et al., **Which Agent Causes Task Failures and When? On Automated Failure Attribution of LLM Multi-Agent Systems**,
arXiv **2505.00212**, ICML 2025. Code https://github.com/mingyin1/Agents_Failure_Attribution ;
data https://huggingface.co/datasets/Kevin355/Who_and_When (revision used by Knosis: `59b9fcba1aaed7bbf206b5f4d3c68b8face2f49c`).
License: not declared on the data card; check with the authors before redistributing.

Get it: `knosis download whoandwhen` (fetches the revision above into `data/whoandwhen/`),
which gives `data/whoandwhen/Who&When/{Algorithm-Generated,Hand-Crafted}/<n>.json` (about 9 MB; the same directory also has two parquet files, which Knosis does not read).

## Description

- 184 failure logs: 126 Algorithm-Generated (expert teams auto-generated by CaptainAgent, AG2 group chat, with each agent's system prompt),
  58 Hand-Crafted (Magentic-One: Orchestrator, WebSurfer, FileSurfer, Assistant, ComputerTerminal). Tasks come from GAIA and AssistantBench.
- Annotations (done by the paper's authors following an annotation guideline): `mistake_agent` (the agent that caused the failure), `mistake_step` (the decisive error step, a history index starting from 0),
  `mistake_reason` (the reason in natural language); there are also `ground_truth` / `groundtruth` (the task's reference answer) and `is_correct` / `is_corrected` (all false).
- When traces are converted to ATIF, each history entry is one step, with step number = index + 1; in Hand-Crafted, `human` is a user step, and the agent name is `role` with the parenthetical removed
  (`Orchestrator (-> WebSurfer)` is recorded as Orchestrator, with the original role kept in `extra.knosis.speaker`); Algorithm-Generated uses `name`,
  and `Computer_terminal` is the terminal that executes code, counted as a separate agent. The question is placed in `extra.knosis.task` and takes no step number.
- None of the above annotations or reference answers go into the workspace; with `-o answer=true` the question includes the reference answer (the paper's with-ground-truth setting).
- Metrics: agent-level accuracy, step-level accuracy (counted separately). The best method in the paper gets agent 53.5%, step 14.2%; o1 and R1 also fall short of a usable level.
- scenario: `all`, `algorithm`, `hand`; the exporter splits by log, by default dev 10 / test 30.

## Pitfalls

- In 2 Hand-Crafted logs the casing of `mistake_agent` differs from the agent name in the log: scoring ignores case.
- In 6 logs the speaker at the error step is not the annotated agent. Upstream keeps them as is; agent and step are scored separately.
  (Which ones they are and what the annotation pattern is are not written here: the agent can also read the data card.)
- The "decisive error step" is itself subjective (the paper discusses annotator disagreement; details to be verified), so step-level accuracy is a noisy metric.
- Agents in the logs sometimes state or guess the correct answer; that is log content, not leakage.
