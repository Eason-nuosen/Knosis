# Who&When — failure attribution for multi-agent systems ($scenario)

## What the data is

Each question is the run log of a multi-agent system that **has already failed** (tasks from GAIA and AssistantBench): `data/traces/<id>.json` is the ATIF trace,
`data/traces/<id>.md` is for reading, `## step <n>` is the step number, and the speaking agent is in the step heading. Two kinds of systems:
expert teams auto-generated by CaptainAgent (`ag-*`, $n_algorithm logs; `Computer_terminal` is the terminal that executes code and also counts as an agent;
each agent's system prompt is in `extra.knosis.agents` of the `.json`), and the hand-built Magentic-One (`hc-*`, $n_hand logs;
the Orchestrator dispatches WebSurfer, FileSurfer, Assistant and ComputerTerminal).
$answer_note

## What the downstream task is

For each log, identify the **agent that caused the failure** and the **decisive error step** (the step where the critical error happened; later errors are often its consequences).
`tasks/dev.jsonl` has $n_dev dev logs; the test logs ($n_test) are given in the decide stage; each question has `question`, `trace`,
`agents` (the agents appearing in the log) and `n_steps`.

Deliver `predictions.jsonl`, one line per log:

```json
{"id": "hc-12", "answer": {"agent": "WebSurfer", "step": 13, "reason": "Clicked into an irrelevant web page, and all later searches went off track"}}
```

`step` is the step number in the `.md` (starting from 1). Metrics: fraction of correct agents and fraction of correct steps (as upstream, the two are counted separately).
Step-level judgment is hard (the best method in the paper gets about 14%); agent level is about 54%; the expected accuracy of random guessing is given in the reference baseline of the evaluation report.

## What the knowledge should serve

Make unseen failure logs attributed correctly as well: typical failure modes of each kind of agent (search going off track, concluding without verification, code not handling edge cases, premature termination, etc.),
how to trace back from consequences to the first critical error, which steps merely relay or execute and should not be blamed, and the log structure of each of the two kinds of systems.
Knowledge should be reusable; it should not cache answers to specific logs; the annotations in dev feedback are only for testing and correcting these patterns.
