Knosis

knowledge+gnosis

Knosis（knowledge + gnosis）是面向 agent 的知识底座：既能让个人 agent 从日常使用轨迹里累积知识，也能让 agent 在企业级任务上累积对任务和数据的理解。每条知识都带来源、证据和状态，可审计、可撤回、可继承。

知识的格式、证据、内化、选取与继承是同一套；区别只在知识从哪里来、拿去做什么。

主打

知识在执行中产生，在环境里验证

不同于从文档出发的 wiki 式知识库，Knosis 的知识由 agent 在做任务时总结出来，每一条都要拿数据、工具或反馈去支持或反驳。失效的知识可以撤回并向下游传播。

特点

知识，不是记忆，也不是 skill

判别标准只有一条：能不能被环境中的证据反驳。能被反驳的才算知识。三者 Knosis 都管，但分开存放、分开评价。

memoryskillknowledge（Knosis）
内容发生过什么、看到过什么怎么做一件事关于环境 / 数据的带条件断言
能否判真假只是记录看好不好用能，可被支持或反驳
价值标准能检索到任务成功正确性与收益分开衡量
和读者的关系绑定某个 agent和读者能力有关真假不依赖读者，收益依赖读者
怎么更新追加改写证据驱动：接受、收窄条件、撤回并向下游传播

可审计

每条知识有来源（数据位置、工具调用、反馈题目、轨迹步骤）和证据链。

可撤回

父单元被撤回，派生出的后代跟着撤回或失效；数据指纹变了，旧证据自动过期。

正确 ≠ 有用

按任务选取是单独一步；有没有用写成 usage 元知识，由 dev 反馈和消融检验。

不绑定 agent

Knosis 不自己当 agent：同一份知识库可以给 Codex、Claude Code 或任何 MCP 客户端读。

记什么

只记能被环境反驳的知识

会记下

  • 项目约定：目录结构、入口、测试怎么跑
  • 数据的坑：编码、缺失值、不唯一的键
  • 工具与命令在这台机器上的实际行为
  • 报错的原因，以及怎么解决的
  • 方法：如何发现或验证某类知识

不会记

  • 用户偏好与对话记忆（无法被环境反驳）
  • 一次性的具体任务答案
  • 闲聊
  • 密钥、token 与口令
  • 轨迹支持不了的说法保持 inferred，不会标为 verified

工作区

探索、抽取、修订、决策

Knosis 逐阶段驱动 agent（或 agent 读 AGENTS.md 自己推进）。每个阶段都验收并提交 git；agent 看不到测试答案，也不能运行评测。

01explore

摸清数据，提出候选断言

02extract

写成带条件与来源的 κ，快照 K_0

03refine × n

提交 dev 预测，读逐题反馈，修订知识

04consolidate

去重、矛盾、体系；每步验收或回滚

05decide

选取知识作答测试题，记录用到哪些知识

每个工作区有反馈预算；dev 与测试题不重叠；反馈可以给答案，也可以只给对错。

为什么要内化
知识库会越收越多：同一件事被重复记下、新证据推翻旧结论、环境变了旧知识过期。不整理，检索到的就是重复、互相打架、彼此孤立的知识。
