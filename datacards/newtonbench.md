## License

Code **MIT** (`LICENSE` at the repo root); paper **CC BY-NC-SA 4.0** (non-commercial).

**The two differ.** Reuse code under MIT; mind the NC clause when quoting the paper text.

⚠️ This benchmark **has no data artifacts**, so there is no "dataset license" to speak of
and no data file needing separate permission. Knosis reads source code.

## Obtaining

```bash
knosis download newtonbench     # git clone the upstream repo into data/newtonbench/
```

- **No HuggingFace dataset, no PyPI package, no downloadable data artifact of any kind.** Source code only.
- The simulators use numpy and **need no API key to run**; but upstream's default evaluation uses an LLM judge
  (default `nemotron-ultra`), **which needs a key, so symbolic accuracy cannot be computed offline**.
- Do not expect to `load` an x/y table after cloning: no such table exists on disk.

## Size

**There is no "dataset" to load.** Tasks are *generated* by the harness at run time:
the agent actively probes the simulator through the `<run_experiment>` tool (give a set of input parameters, get the output back),
and the ground-truth equations live as Python functions in `modules/m*/laws.py`.

| Dimension | Values | Count |
| --- | --- | --- |
| Physics domain | `m0_gravity` … `m11_heat_transfer` | 12 |
| Difficulty | `easy` / `medium` / `hard` | 3 |
| Version | `v0` / `v1` / `v2` | 3 |
| **Counterfactual laws** | 12 × 3 × 3 | **108** |
| System complexity | `vanilla_equation` / `simple_system` / `complex_system` | 3 |
| **Total tasks** | 108 × 3 | **324** |

⚠️ **Reading it as "12 domains × 3 difficulties = 36" undercounts by a factor of 3.** Difficulty and version are orthogonal dimensions;
in `evaluation_results/`, `{difficulty}/{version}` are two nested directory levels.

**The two dimensions differ in nature:**

- **Difficulty** `easy` / `medium` / `hard`: set by **the number of mutations applied to the expression**. Mutations are **cumulative**:
  easy = 1–2 mutations from the canonical law; medium = easy plus 1–2 more; hard adds more again.
- **Version** `v0` / `v1` / `v2`: different mutations at the same difficulty.

Mutations are operations on the expression tree (swap an operator, e.g. `+` -> `×`; change a constant/exponent, e.g. square -> cube).
Four curation rules: no new variables, complexity must not decrease, a mutation must not invert the previous one,
and two consecutive mutations must not be equivalent to a single one.

The 12 physics domains (directory name -> physics, directory names verbatim):

| Directory | Physics |
| --- | --- |
| `m0_gravity` | Universal gravitation |
| `m1_coulomb_force` | Coulomb force |
| `m2_magnetic_force` | Ampère force / magnetic field |
| `m3_fourier_law` | Fourier heat conduction |
| `m4_snell_law` | Snell refraction |
| `m5_radioactive_decay` | Radioactive decay |
| `m6_underdamped_harmonic` | Underdamped harmonic oscillation |
| `m7_malus_law` | Malus's law (polarization) |
| `m8_sound_speed` | Speed of sound |
| `m9_hooke_law` | Hooke's law |
| `m10_be_distribution` | Bose-Einstein distribution |
| `m11_heat_transfer` | Heat transfer |

**Three system-complexity levels**: `vanilla_equation` (bare equation) / `simple_system` / `complex_system`.
The latter two add "auxiliary equations"; the agent is told the auxiliary equations but not the target law.
Simple averages **1.75 auxiliary equations / 5.17 operations**, Complex averages **2.42 / 8.17**.

**Variables and ranges**: variable names and meanings are a **prose description** (the `PARAM_DESCRIPTION` string in `prompts.py`);
ranges follow a **log-uniform sampling** convention, e.g. in `m0_gravity` the two masses are `U_log(10^0, 10^3)`
and the distance is `U_log(1, 10^1)`. In source this is
`np.exp(np.random.uniform(np.log(1), np.log(1e3)))`.

⚠️ **No units / dimensions metadata.** The repo has no structured table of units or dimensions anywhere;
units appear only in **comments on tolerance constants** (like `1e-9  # meters`).
So a "physical schema + dimensions" must be supplied by the user; Knosis passes on only the prose
`PARAM_DESCRIPTION` and the function signature.

## Scoring

Upstream has two tracks; **do not mix them**:

- **Symbolic Accuracy (SA)**: binary; an **LLM judge** decides symbolic equivalence,
  **deliberately ignoring physical constants**. The default judge is `nemotron-ultra` (the paper reports **98.3%** agreement with humans).
  The judge tolerates renamed variables and rewritten constants, but **not changed exponents** ("exponent 4 and 4.03 are different").
  **Cannot run offline: this step needs an API.**
- **RMSLE**: data fidelity, computed on **5000 held-out samples**, with Modified Z-Score outlier removal.
  Upstream **explicitly rejected NMSE** in favor of RMSLE.

Upstream findings:

- Noise of even **0.0001** drops SA by **12–16%**.
- **Giving strong models code assistance lowers performance** (a shift from exploration to exploitation), while weak models improve.
- Paper numbers are the mean and standard deviation over **four runs**.

Good for: active experimental design, symbolic regression, counterfactual reasoning, dimensional analysis.
Not good for: reading as an ordinary x/y tabular dataset (**no such table exists on disk**).

## How Knosis uses it

- Loader (`knosis/data/loaders/newtonbench.py`): scenario is a domain (default `m0_gravity`). Each domain yields
  27 tasks (3 difficulties × 3 versions × 3 systems), id `<domain>/<difficulty>/<version>/<system>`;
  the input is the `PARAM_DESCRIPTION` from `prompts.py` taken verbatim (not parsed), the answer points to
  `laws.py::_ground_truth_law_<difficulty>_<version>`. `upstream()` imports the upstream `modules.<domain>` package
  with `utils.call_llm_api` stubbed out and the LLM symbolic check disabled.
- Exporter (`knosis/workspace/exporters/newtonbench.py`): no data files; the GT law stays in the raw directory and
  the agent runs experiments through the `newton` tool. The three systems at the same (difficulty, version) share one law,
  so dev and test are split by whole (difficulty, version) groups (default `dev=2` groups) and dev feedback cannot leak a test law.
  Options: `noise` (relative observation noise, upstream default 0), `systems` (restrict to e.g. `vanilla_equation`).
  Output: `predictions.jsonl` (a `discovered_law` function per task).
- Scorer (`knosis/decision/newtonbench.py`): calls upstream `evaluate_law` (RMSLE over 5000 points, sampled as upstream,
  with `np.random.seed(0)` before each task for reproducibility) with the LLM judge disabled.
  `ok` means RMSLE ≤ 0.01, a Knosis convention (upstream's success criterion is symbolic equivalence).
  Reported: `ok_rate`, `rmsle_median`, `invalid` (NaN RMSLE), `missing`. **Symbolic accuracy is not implemented** (needs an LLM judge).

## Known issues

- ⚠️ **There is no "dataset" to load.** Tasks are generated by the harness at run time,
  the ground truth is in source code, and input points must be probed from the simulator by the agent. Knosis **produces no x/y table** (none exists).
- **Ground truth lives in code**: `LAW_REGISTRY` in `modules/m*/laws.py`, structured as
  `{'easy': {'v0','v1','v2'}, ...}`.
  **There is no export format** (no JSON manifest); to make a data artifact you have to export it yourself.
- **The ground-truth function signature differs from the one shown to the LLM**: internally it is
  `_ground_truth_law_easy_v0(mass1, mass2, distance)`, while submissions must be
  `def discovered_law(...)`, bridged by `parameter_mapping`.
- ⚠️ **Every target law embeds at least one "rescaled physical constant"** to restore the dimensional consistency broken by mutation.
  In source it appears as `HIDDEN_CONSTANT`, e.g. **`6.674e-5`** for `m0_gravity`.
  **This is not the real gravitational constant; do not "correct" it.** Prompts expose it as `HIDDEN_CONSTANT_C`,
  and **it must not be a function parameter** (it must be defined as a local variable inside the function body).
  The judge ignores constant values, but **RMSLE does not**.
- **Some laws are physically implausible** (acknowledged in the upstream paper): mutations keep dimensions consistent, but some forms
  do not hold in our universe, e.g. some hard variants of `m8` and `m10`:
  **certain inputs produce NaN / inf**; the code has guard clauses and `float('nan')` branches,
  and the metric code filters them explicitly. **Do not treat these as load failures.**
- **Randomness**: `core.py` uses bare `np.random.uniform` **with no visible global seed**;
  **reproducibility is not guaranteed by default** (paper numbers are mean ± std over four runs).
- **Variable metadata is prose, not an authoritative declaration.**
- **No dimensions**: upstream has no structured unit table; units appear only in comments on tolerance constants.
